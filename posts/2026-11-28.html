A coding app that understands pictures and folders, plus RAG basics

A quiet news day, so here is one useful tool update, one older resource for running models at home, and a plain walk through retrieval-augmented generation.

What matters today

  1. pingdotgg/t3code T3 Code Nightly 0.1.14-nightly.20261128.5385 (0eeb7d10c8f3)

    T3 Code, an app for working with AI coding agents, has a new nightly test build. You can now draw on images you attach, attach whole folders, save files to your own computer, and see how much of your machine's memory and processor is in use. It also adds task lists for the agent and image diffs, which show before and after versions of an image side by side. Because it is a nightly build, expect rough edges.

    Real-world example

    A freelancer building a booking page for a hair salon could screenshot the page, circle the broken button, and attach it with the note "make this match the header." Then they could check the image diff to confirm only that button changed.

    How you could use it

    If you often explain layout bugs in long paragraphs, try marking up a screenshot instead. Attaching a whole folder can save you from pasting files one at a time when the agent needs context. The resource monitor helps you notice when an agent run is slowing down your machine. Since this is a test build, try it on a side project before you rely on it for real work.

Worth knowing

  1. Introducing the llama.cpp benchmark dashboard for AMD Ryzen and Radeon

    The team behind llama.cpp, a popular free tool for running AI models on your own computer, launched a benchmark dashboard. It tracks how fast models run on AMD Ryzen processors and AMD Radeon graphics cards. That makes it easier to judge whether your current hardware is good enough before you spend money or hours on setup.

    Real-world example

    A small accounting office that wants to summarize client documents without sending them to an outside service could check the dashboard to see whether their existing AMD desktops can run a local model at a usable speed.

    How you could use it

    Before you build a feature that runs a model on the user's own machine, look up similar hardware on the dashboard so you can set realistic expectations. You could also use it to choose a model size that fits the AMD machines your users actually own.

Technique of the day

Retrieval-augmented generation

Retrieval-augmented generation, or RAG, means looking up the right documents first and then handing them to the model along with the question. Your documents are split into small chunks, and each chunk is turned into a list of numbers that captures its meaning. These are stored in a vector store, which is a database that finds chunks with similar meaning. When a question comes in, you fetch the closest chunks and tell the model to answer only from them, so it relies on your facts instead of guessing.

Try it

Paste three to five short documents, such as policies or FAQ entries, into a chat, then send:
Using only the documents above, answer: [your question].
Quote the sentence you relied on.
If the answer is not in the documents, say "not found".
Then ask something the documents do not cover and check that it says "not found".
