Skills that arrive with your tools, and agents that wait for your OK

Claude Code can now pick up skills straight from connected tool servers, and T3 Code adds multi-repo projects plus workflows that pause for approval.

What matters today

  1. anthropics/claude-code v2.1.332

    Claude Code 2.1.332 adds a beta feature that lets it load skills from MCP servers. MCP, the Model Context Protocol, is a standard way to plug outside tools and data into an AI assistant, and skills are packaged instructions that teach the agent how to do a specific job. The release also adds a new hook event called PreSkillShellCommand. A hook is a small script you set up to run automatically at a set moment, and judging by its name this one fires just before a skill runs a terminal command.

    Real-world example

    A small accounting firm could run one tool server that both connects Claude Code to its bookkeeping system and ships a skill that explains how to reconcile a month correctly. Anyone on the team who connects that server gets the know-how along with the access, with no instruction files to copy around.

    How you could use it

    If you maintain an MCP server, you could bundle a skill alongside it so the agent learns the right way to use your tools, not just that they exist. You could also add a PreSkillShellCommand hook that logs or blocks risky commands before any skill runs them, which is a sensible guardrail before you install skills from servers you did not write. Since this is beta, try it on a test project first.

  2. pingdotgg/t3code T3 Code v0.1.12

    T3 Code v0.1.12 lets one project span several code repositories, and each piece of work runs in its own worktree. A worktree is a separate working copy of the code, so parallel agent tasks do not overwrite each other. It also adds beta durable workflows: multi-step jobs that can pause for a human approval and run on a schedule. Threads can now be linked across machines too.

    Real-world example

    A two-person agency with a separate website repo and mobile app repo could set up one project covering both. A scheduled workflow could have an agent prepare a weekly dependency update in an isolated copy, then stop and wait until someone approves it before anything is merged.

    How you could use it

    If you split an app across a frontend repo and a backend repo, you could manage both as one project and let agents work on them side by side without clashing. You could also try a durable workflow for routine chores like nightly test fixes or weekly cleanups, with an approval step so nothing lands unreviewed. Treat the workflow part as beta and keep it to low-risk jobs at first.

Worth knowing

  1. OpenAI and Cisco introduce Shirudo

    OpenAI and Cisco released Shirudo, an open-source Linux runtime that helps teams protect running systems while security patches are still being rolled out. Open-source means the code is public and free to use. It targets the risky gap between a known problem and a fix actually being installed everywhere.

    Real-world example

    A regional online store running a few Linux servers could learn about a serious flaw on a Friday evening but not be able to patch until Monday. A protective layer like this could help cover that weekend window.

    How you could use it

    If you self-host a side project or a small business app on Linux, it could be worth evaluating Shirudo as an extra safety layer between updates. Read its docs to see what it covers before relying on it, and keep patching as quickly as you can.

Technique of the day

Project notes for agents

Project notes for agents means keeping a short file in your project that the AI agent reads before it starts any task. It holds the things you would otherwise repeat every session: how to run the app, which folders matter, coding rules, and decisions you have already made. Because the agent reads it first, it makes fewer wrong guesses and you spend less time correcting it. Keep it short and update it whenever you catch yourself explaining the same thing twice.

Try it

Create a file named CLAUDE.md in your project root with:
# Project notes
- Run the app: (your start command)
- Run tests: (your test command)
- Never edit: (generated or vendor folders)
- Style: (one or two rules you care about)
- Decisions: (one past choice and why)
Then ask your agent: Read CLAUDE.md and tell me anything that looks unclear.
